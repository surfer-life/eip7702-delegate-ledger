How this is made

  1. Every day a public GitHub Action reads about 7,200 Ethereum blocks from a public node and counts every EIP-7702 authorization by the contract it points at.
  2. For each contract it collects what anyone can check: is the source published (Blockscout and Sourcify), does the explorer flag it, who submitted the authorizations.
  3. It then asks a node to simulate sending 1 wei to a few accounts delegated to each contract (eth_simulateV1; nothing is sent) and records whether the ETH is passed on, and to whom.
  4. The lookup above runs in your browser. It asks public nodes for the address's code and the USDC/USDT issuer blacklists, runs the same dry run for a delegated address, and matches the result against the ledger.

What the labels mean

known malicious
The explorer flags it, or its own published source says it is an exposed scam contract.
flagged by research
Marked as a malicious delegate on Ethereum in a peer-reviewed dataset (Huang et al., USENIX Security 2026).
passes incoming ETH on
In a dry run, ETH sent to sampled accounts delegated to it left again in the same transaction. Behaviour, not intent: some collection setups do this on purpose.
published source forwards funds
The source is public, and it says incoming ETH is sent on to another address.
resembles known malicious
No published source, but its bytecode is at least 90% the same as a known malicious contract, with the same functions.
source not published
Nobody can read what it does without decompiling. Not proof of harm: in a hand sample these ranged from trading tools to collection schemes to scams.
source published
The code is public and matches. Not a safety verdict.
no evidence this run
A source did not answer, so no label is given.
